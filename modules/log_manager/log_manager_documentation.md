# توثيق مدير السجلات (Log Manager Documentation)

## نظرة عامة

وحدة **Log Manager** هي المكون الأساسي المسؤول عن استلام، معالجة، وتخزين جميع السجلات والأحداث الأمنية الصادرة عن وحدات `bunyanx` المختلفة. يعتمد النظام على بنية غير متزامنة (Asynchronous) لضمان عدم تأخير معالجة الحزم الشبكية أثناء عملية التسجيل.

## المعمارية الفنية

1. **قناة الاستلام (Event Channel):** ترتبط وحدة Log Manager بـ `EventBus` المركزي وتستمع للأحداث ذات الأولوية (INFO, WARNING, CRITICAL).
2. **التخزين الهجين (Hybrid Storage):**
   - **سجلات تشغيلية (Operational Logs):** تُخزن في ملفات نصية (تناوب السجلات - Log Rotation) داخل مجلد `var/logs/` لاستكشاف الأخطاء الفنية.
   - **سجلات أمنية (Security Logs):** تُخزن في قاعدة بيانات `bunyanx_events.db`، والتي تضم جداول مخصصة مثل `threat_events` و `access_logs`.
3. **التجميع (Aggregation):** يقوم النظام بتجميع السجلات المتكررة (مثل هجوم حجب الخدمة DDoS) لتقليل حجم البيانات التخزينية المهدورة.

## هيكلية السجل (Log Structure)

يتم تمرير الأحداث بصيغة JSON مهيكلة:

```json
{
  "timestamp": "2026-06-16T12:00:00Z",
  "module": "firewall",
  "level": "CRITICAL",
  "event_id": "FW-DROP-1092",
  "src_ip": "192.168.1.100",
  "dst_ip": "10.0.0.5",
  "action": "DROP",
  "message": "Matched malicious signature ID 44"
}
```

## الارتباط بنظام التحكم المركزي

يتيح الـ Log Manager واجهة برمجة تطبيقات (API) مدمجة مع `System Control Plane` تسمح للمسؤولين بالاستعلام السريع عن السجلات عبر لوحة التحكم Web UI وعرض إحصائيات بيانية حول معدلات الهجوم والأنشطة المشبوهة في الوقت الفعلي.
