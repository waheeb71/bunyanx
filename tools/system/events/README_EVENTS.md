# البنية المعمارية — Event Bus (الجهاز العصبي للنظام) 📨

يُمثل مجلد `system/events` الناقل المركزي والعمود الفقري الذي يربط جميع وحدات الجدار الناري ببعضها (Decoupled Architecture). باستخدام معمارية مبنية على الأحداث (Event-Driven)، لا تحتاج الموديولات (مثل WAF) للتحدث المباشر مع النواة (Core)؛ بل تكتفي بإصدار "حدث" ليقوم الناقل بتوزيعه فوراً لمن يهمه الأمر.

---

## 📂 خريطة ملفات المجلد

### 1. `bus.py` (ناقل البريد الذكي)
هذا هو المحرك الأساسي للمجلد، مصمم ليعمل في الخلفية بسرعة هائلة، ويمتلك 3 آليات للعمل (Backends) حسب إعدادات الـ Feature Flags:
* **`MemoryBackend` (الأداء المحلي):** يستخدم طابوراً محلياً `asyncio.Queue` بسعة 10,000 حدث كحد أقصى. يوفر سرعة استجابة تقترب من الصفر مللي ثانية (Zero-latency Publishing). مزود بـ **درع حماية للذاكرة (Backpressure)** يقوم بإسقاط الأحداث الجديدة إذا امتلأ الطابور لمنع انهيار الخادم أثناء هجمات الـ DDoS.
* **`NATSBackend` (الإنتاج الموزع):** يستخدم تقنية NATS JetStream لتبادل الأحداث عبر شبكة الخوادم (Cluster) بزمن وصول منخفض جداً.
* **`NullBackend`:** معطل (لا يقوم بأي عملية).

*ميزة الحماية التلقائية (Auto-Validation):* الناقل يقوم تلقائياً بحقن حقلي `event_id` و `timestamp` في أي رسالة قادمة لا تحتويهما لضمان استقرار الأنظمة المستقبلة.

### 2. `schemas.py` (قوالب البيانات الصارمة)
لحماية الجدار الناري من تناقض البيانات، يفرض هذا الملف هياكل بيانات (Dataclasses) إلزامية لكل نوع من الأحداث. 
من أهم القوالب المتاحة:
* `ThreatDetectedEvent`: لتنبيه النظام عند اكتشاف هجوم (يحتوي على نوع التهديد، IP المهاجم، الثقة).
* `ResponseBlockEvent`: إشارة مباشرة إلى نواة لينكس بحظر عنوان IP.
* `PacketInspectedEvent`: ملخص فحص حزمة بيانات.

### 3. `topics.py` (قاموس الترددات)
ملف بسيط وظيفته منع الأخطاء الإملائية. يجمع كافة قنوات البث (Topics) في كلاس واحد مثل:
* `Topics.THREAT_DETECTED` = `"threat.detected"`
* `Topics.MODULE_HEALTH` = `"module.health"`

---

## 🔄 دورة حياة الحدث (مثال عملي)
1. محرك الـ VPN يكتشف محاولة دخول فاشلة متكررة.
2. يستدعي: `await bus.publish(Topics.THREAT_DETECTED, payload)`
3. الناقل يستلم الحدث ويرميه في الطابور (Queue) في الخلفية فوراً دون تأخير الـ VPN.
4. المستمع 1 (محرك الفحص Correlation) يلتقط الحدث ويبدأ في دراسة سلوك المستخدم.
5. المستمع 2 (جسر التسريع eBPF) يلتقط الحدث ويقوم بحظر الـ IP فوراً.
